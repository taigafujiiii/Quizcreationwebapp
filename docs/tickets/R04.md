# R04: ルート分割 + ErrorBoundary

## 目的
`App.tsx` が全 13 ルートのコンポーネントを静的 import しており、コード分割ゼロ（`React.lazy`/dynamic import 使用 0 件）。単一 JS チャンク 671KB(gzip 192KB) となり、Vite の「500KB 超チャンク」警告が発生している。学生（受講生）ユーザーも管理画面全部（`AssignmentsManagement` 1849 行を含む）をダウンロードしてしまう（DESIGN.md P1-1）。`React.lazy` + `Suspense` で管理系/学生系（可能ならルート単位）をコード分割し初回 DL を削減する。あわせて、`Suspense` の遅延ロード失敗や描画時例外での白画面クラッシュに備え、`ErrorBoundary` を新設しトップレベル適用する（DESIGN.md S7 後半）。外部から見た挙動（画面・遷移・機能）は変えない。

## 対象ファイル
- `src/app/App.tsx`（1〜19行目の全ルートコンポーネント静的 import、51〜79行目 `AppRoutes`、81〜92行目 `App`）
- `src/app/components/common/ErrorBoundary.tsx`（**新設**。配置ディレクトリが無ければ作成）
- 参考（変更しない・パターン流用元）: `App.tsx` 27〜33行目 `AdminRoute` のローディング UI（`<div className="min-h-screen flex items-center justify-center bg-gray-50"><div className="text-gray-500">読み込み中...</div></div>`）
- 参考（変更しない・現状把握）: `vite.config.ts`（`outDir` 未指定 = `dist/`、`manualChunks` 未設定、エントリ `src/main.tsx`）

## 実装手順
1. **ルートコンポーネントの `React.lazy` 化**
   - `App.tsx` 5〜20行目の各画面コンポーネント import を `React.lazy(() => import('...').then(m => ({ default: m.Xxx })))` 形式へ変更する（各コンポーネントは名前付き export のため `default` へマップするラッパーが必要）。
   - 対象ルート（少なくとも管理系/学生系の 2 分割。推奨はルート単位での個別 lazy 化）:
     - 管理系: `AdminDashboard`, `UnitsManagement`, `CategoriesManagement`, `QuestionsManagement`, `AssignmentsManagement`, `UsersManagement`, `CompaniesManagement`
     - 学生系: `Home`, `QuizSetup`, `Quiz`, `Result`, `UnitSelect`, `CategoryList`
     - 公開系（`Login`, `Forgot`, `SelectCompany`）は初回描画に必要なため eager のまま残してよい（バンドル小。判断は実装者、ただし lazy 化しても可）。
   - ルート単位で `React.lazy` すると Vite が dynamic import ごとにチャンクを自動生成するため、「最低限 2 分割」要件を満たしつつより細粒度になる。**この方式を推奨**。厳密に「管理系 1 チャンク / 学生系 1 チャンク」の 2 チャンクに束ねたい場合のみ、`vite.config.ts` の `build.rollupOptions.output.manualChunks` でグルーピングする（任意）。
   - `Toaster`（21行目）は常時表示のため eager のまま。`AuthProvider`/`CompanyProvider`（R03 で memo 化済み）も eager のまま。
2. **`Suspense` フォールバック**
   - `AppRoutes` の `<Routes>...</Routes>` を単一の `<Suspense fallback={<ローディングUI />}>` でラップする（各ルート個別ラップでも可だが、共通フォールバックが簡潔）。
   - フォールバック UI は既存の `AdminRoute` ローディングパターン（`min-h-screen flex items-center justify-center bg-gray-50` + `text-gray-500`「読み込み中...」）に合わせる。共通コンポーネント化しても、インラインでも可。
   - `AdminRoute`/`StudentRoute` のガード（loading 中の表示、未ログイン/会社未選択リダイレクト）は現状の挙動を維持する。
3. **ErrorBoundary 新設**
   - `src/app/components/common/ErrorBoundary.tsx` にクラスコンポーネントを新設。`getDerivedStateFromError` と `componentDidCatch` を実装し、`hasError` 時はフォールバック UI（既存トーン: `min-h-screen ... bg-gray-50`、メッセージ + 「再読み込み」ボタン等）を表示する。子は `props.children` を描画。
   - フォールバックはアプリ既存の見た目に合わせる（`Header` 依存や router hooks は使わない＝ ErrorBoundary は Router 内外どちらでも安全に動くよう router 非依存にする）。
4. **トップレベル適用**
   - `App`（81行目〜）で `ErrorBoundary` を最上位に適用する。`<ErrorBoundary><BrowserRouter>...</BrowserRouter></ErrorBoundary>` を基本とする（Provider/Router 全体を保護）。`Suspense` の内側にも境界が必要なら二重に置いてよいが、最低限トップレベル 1 箇所は必須。
5. **スコープ境界（重要）**
   - 本チケットは **S7「後半」= ErrorBoundary 新設・適用のみ**。`Result.tsx` の `location.state` 未チェック修正（S7「前半」）は **R10 の担当**であり R04 では行わない。ErrorBoundary は Result 直アクセス時のクラッシュを「白画面 → フォールバック表示」に緩和する安全網として機能するが、根本修正は R10。

## 完了条件
- `npm run typecheck`（R02）がエラーなく完了する。
- `npm run build` が成功し、Vite の「500KB 超チャンク」警告が解消または大幅緩和される。
- コード分割が行われている: `dist/assets/` に管理系/学生系のルートチャンクが分離生成される（`React.lazy` によるチャンク数増）。
- **実測値の記録**（PR/報告に必須）:
  - 変更前後の `npm run build` 出力から「生成チャンク数」と「メイン(エントリ)チャンクの gzip サイズ」を記録する。
  - ベースライン: 単一 JS チャンク 671KB / gzip 192KB。**目安: メインチャンク gzip 30% 以上削減**（≒ 134KB gzip 以下）。
  - 未達の場合は原因を報告する（例: `supabase-js` 165KB や共通 UI/Provider がメインチャンクに残存。これらは P1-2=R07/軽量化検証の領域で本チケット範囲外）。未達＝失敗ではなく、原因分析の記載で完了とする。
- 外部挙動が不変であること: 全ルートの表示・遷移・ガード（未ログイン→/login、会社未選択→/select-company、非 admin→/）が従来通り。遅延ロード中は「読み込み中...」フォールバックが表示される。
- `ErrorBoundary` がトップレベルに適用され、配下の描画時例外でアプリ全体が白画面化せずフォールバックが表示される。

## 備考
- 名前付き export を `React.lazy` する際は `import('./components/admin/QuestionsManagement').then(m => ({ default: m.QuestionsManagement }))` のように `default` へマップする。
- メインチャンク gzip 30% 削減はルート分割単独では未達の可能性がある（`react`/`react-dom`/`react-router`/`supabase-js`/共通 UI/Context はエントリ側に残るため）。その場合の追加削減は R07（Supabase 軽量化検証）や R01（未使用依存削除）の領域。本チケットは「分割できていること」と「実測値の記録＋未達原因の報告」までを達成基準とする。
- `manualChunks` を使う場合も、外部挙動（遷移・表示）に影響しないことを確認する。
- ソースコードの実変更・新規ファイル作成は本チケット実装フェーズで行う。本ファイルは仕様のみ。

## 要確認
- メインチャンク gzip 30% 削減目標について、P1-2（`supabase-js` 165KB 排除 = R07 検証段階）未実施の状態では未達の可能性が高い。「未達時は原因報告で完了」という達成基準で問題ないか。
