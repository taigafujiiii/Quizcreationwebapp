# X01: xlsx 基盤 — ライブラリ導入 + フォーマット定義

## 目的

4択問題の xlsx インポート/エクスポート機能(要件①)の**土台**を用意する。具体的には (1) SheetJS CE 0.20.x を動的 import 前提で導入し、(2) 新設ファイル `src/app/lib/questionXlsx.ts` に **12 列フォーマットの列定義・`Question[]`⇔xlsx 行変換・行単位バリデーション**を純関数として実装する。

このファイルが DESIGN.md「要件① 1. 実装順序とフォーマットの正」に定めた**フォーマットの単一の真実(single source of truth)**であり、後続の X02(エクスポート UI)・X03(インポート RPC)・X04(インポート UI)がすべてこの定義を参照する。本チケットは UI・DB には触れない(純ロジック + 依存追加のみ)。純関数は Playwright テストランナーの Node 実行で検証する(新規テストランナー追加は不要)。

## 実装手順

### 1. SheetJS CE の導入(禁止事項の例外・DESIGN 承認済み)

`package.json` の `dependencies` に、npm レジストリ版(0.18.5=既知脆弱性未修正)ではなく**公式 CDN 配布の 0.20.x 系 tgz** を URL 指定で追加する:

```jsonc
"dependencies": {
  // ...既存...
  "xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"
}
```

- 0.20.x 系の最新(執筆時点 0.20.3)を使用。Apache-2.0・修正済み。
- `npm install` で cdn.sheetjs.com から取得され、`package-lock.json` に resolved URL + integrity が記録される(ネットワーク到達が前提)。
- **静的 import は禁止**。ライブラリ内では `const XLSX = await import('xlsx');` の**動的 import** のみ使用し、メインバンドルに載せない(Vite が自動でチャンク分割)。SheetJS は Node でも動くため、動的 import を含む変換関数は Playwright の Node 実行でそのままテスト可能。

### 2. 列定義(単一の真実)

DESIGN「要件① 2. xlsx 列フォーマット」の 12 列をそのまま定数化する。**この順序・見出しがエクスポート出力の正**。

```ts
export type QuestionColumnKey =
  | 'id' | 'unit' | 'category' | 'text'
  | 'optionA' | 'optionB' | 'optionC' | 'optionD'
  | 'correctAnswer' | 'answerMethod' | 'explanation' | 'isActive';

export interface QuestionColumnDef {
  key: QuestionColumnKey;
  header: string;    // xlsx 上の日本語見出し(エクスポートで出力)
  required: boolean; // インポート時の必須(空セルを行エラーにするか)
}

export const QUESTION_COLUMNS: readonly QuestionColumnDef[] = [
  { key: 'id',            header: 'ID',       required: false },
  { key: 'unit',          header: '単元',      required: true  },
  { key: 'category',      header: 'カテゴリ',  required: true  },
  { key: 'text',          header: '問題文',    required: true  },
  { key: 'optionA',       header: '選択肢A',   required: true  },
  { key: 'optionB',       header: '選択肢B',   required: true  },
  { key: 'optionC',       header: '選択肢C',   required: true  },
  { key: 'optionD',       header: '選択肢D',   required: true  },
  { key: 'correctAnswer', header: '正解',      required: true  },
  { key: 'answerMethod',  header: '回答方式',  required: true  },
  { key: 'explanation',   header: '解説',      required: false },
  { key: 'isActive',      header: '公開',      required: false },
] as const;

export const QUESTION_HEADERS: string[] = QUESTION_COLUMNS.map((c) => c.header);
```

### 3. 値正規化(純関数・行番号非依存)

既存 CSV パーサ(AssignmentsManagement)のロジックを copy-adapt。エラーは**理由文字列のみ**返し、行番号・列名の付与はパーサ(手順5)側で行う。

```ts
type Norm<T> = { ok: true; value: T } | { ok: false; reason: string };

// 回答方式: 'radio'/'checkbox'(英語)+ 'ラジオ'/'チェックボックス'(日本語)を受理
export function parseAnswerMethod(raw: string | undefined): Norm<AnswerMethod>;

// 正解: radio → A/B/C/D の単一 / checkbox → カンマ区切り(A-D 範囲・重複除去・昇順正規化 "A,C")
//        radio に ',' が含まれる等の「正解と回答方式の不整合」もここで検出
export function normalizeCorrectAnswer(raw: string, method: AnswerMethod): Norm<string>;

// 公開: 空 = 公開(true)。'公開'/'非公開' ほか真偽表現(既存 truthy/falsy セット踏襲)
export function parseActiveValue(raw: string | undefined): Norm<boolean>;

// 公開の逆変換(エクスポート用): true → '公開' / false → '非公開'
export function isActiveToLabel(isActive: boolean): '公開' | '非公開';
```

### 4. エクスポート(`Question[]` → xlsx)

```ts
// 純関数: Question[] → 2次元配列(先頭=ヘッダー行)。SheetJS 非依存でテスト容易。
//   - categoryId → category.name(カテゴリ列)、category.unitId → unit.name(単元列)を名前解決
//   - 正解/回答方式/公開は正規化済み表現で出力(= ラウンドトリップ保証。DESIGN 3.5)
export function questionsToAoa(
  questions: Question[],
  opts: { categories: Category[]; units: Unit[] },
): string[][];

// 薄いラッパ(SheetJS 動的 import): AoA → xlsx バイト列。X02 から使用。
export async function aoaToXlsxBytes(aoa: string[][], sheetName?: string): Promise<Uint8Array>;

// 合成: Question[] → xlsx バイト列
export async function buildQuestionsWorkbook(
  questions: Question[],
  opts: { categories: Category[]; units: Unit[] },
): Promise<Uint8Array>;
```

### 5. インポート(xlsx → 行 → バリデーション)

```ts
// 薄いラッパ(SheetJS 動的 import): xlsx バイト列 → AoA(全セル文字列化)。X04 から使用。
export async function xlsxBytesToAoa(data: ArrayBuffer | Uint8Array): Promise<string[][]>;

// 行エラー(DESIGN 3.4 のレポート形式に対応)
export interface RowError { row: number; column: string; reason: string }

// パース済み1行(DB 解決前の中間表現)
export interface ParsedQuestionRow {
  rowNumber: number;      // xlsx 行番号(ヘッダー=1、最初のデータ行=2)
  id: string;             // 空=新規 / 非空=上書き候補(存在検証は X03/X04)
  unitName: string;
  categoryName: string;
  text: string;
  optionA: string; optionB: string; optionC: string; optionD: string;
  correctAnswer: string;  // 正規化済み("A" or "A,C")
  answerMethod: AnswerMethod;
  explanation: string;
  isActive: boolean;
}

// 純関数: AoA → {正常行, エラー配列}。全行走査(1件でもエラーなら呼び出し側で取込中断)。
//   - ヘッダー行照合: QUESTION_COLUMNS の見出しを正とし、既存 CSV パーサ同等の別名
//     (英語名/全角/順不同)も許容。必須列(required:true)の欠落はヘッダーエラーとして errors に追加
//   - 各行: 必須空チェック → parseAnswerMethod → normalizeCorrectAnswer(raw, method)
//           → parseActiveValue の順に検証。NG は該当列の見出しを column にして RowError を push
//   - 単元名/カテゴリ名は「非空」のみ検証(未存在名はエラーにしない=X03 で自動作成)
export function parseAoaToRows(aoa: string[][]): { rows: ParsedQuestionRow[]; errors: RowError[] };
```

### 6. 行分類(ID 一致=上書き / ID 不存在=エラー)を純関数で中央化

DESIGN「3. インポート仕様」の重複判定(ID一致→上書き / ID空→新規 / ID有り+DB不存在→エラー)を、DB 非依存の純関数として提供する。X04 は読み込み済み問題の ID 集合を渡して呼び出し(X03 の RPC が最終的にトランザクションで担保)。

```ts
export type RowResolution =
  | { kind: 'insert'; row: ParsedQuestionRow }
  | { kind: 'update'; row: ParsedQuestionRow }
  | { kind: 'error';  error: RowError };

//   - id 空            → insert
//   - id 非空 ∧ 既存   → update(上書き)
//   - id 非空 ∧ 未存在 → error({ column: 'ID', reason: '指定IDの問題が存在しません' })
export function classifyRows(rows: ParsedQuestionRow[], existingIds: Set<string>): RowResolution[];
```

## 備考

### 正規化関数の扱い(再利用/移設方針)

**推奨: AssignmentsManagement 内のロジックを `questionXlsx.ts` へ copy-adapt(再実装)し、移設・共有化はしない。** 理由:

1. AssignmentsManagement の既存 CSV インポートは DESIGN / TICKETS で「現状維持・機能変更しない(スコープ外)」と明記。関数を移設すると当該ファイルを編集することになり、R06(同ファイルの perf 改修)とのマージ衝突・回帰リスクを生む。
2. 既存関数はコンポーネント内クロージャで、エラーを `行${n}: 理由` の**平坦な文字列**に埋め込む形。X01 は `{ row, column, reason }` の構造化エラーと**行番号非依存の純関数**を要するため、シグネチャが異なる(そのままは流用不可)。
3. ロジックは小さく安定。純関数として複製し単体テストで固定する方が、越境結合より安全。

将来的な DRY 統合(AssignmentsManagement 側が `questionXlsx.ts` を import)は可能だが、CSV インポータを触る別リファクタとして分離すべきで X01 の範囲外。

### バリデーションと DESIGN「3. インポート仕様」の整合

- **ID 一致→上書き / ID 空→新規 / ID 有り+DB 不存在→エラー**: 純関数 `classifyRows`(手順6)に中央化。DB 存在集合は X04 が供給、原子的 upsert は X03 の RPC が担保。
- **単元・カテゴリ自動作成**: 未存在名は**行エラーにしない**(空名のみエラー)。名前解決 + 自動作成は X03(RPC)側で実施。lib は名前を素通しする。
- **全件ロールバック**: lib は「1件でもエラーなら中断」の材料(`errors` 配列)を返すのみ。実際のロールバックは X03(単一トランザクション RPC)。
- **課題フラグ(is_assignment)**: DESIGN 通り xlsx 列に含めない。lib は扱わない(更新時は既存値維持・新規は false を X03 が設定)。

### 要確認事項(PM/オーナー)

- **回答方式の空欄の扱い**: DESIGN の列フォーマット表は「回答方式」を必須(○)とする一方、踏襲元の既存 CSV 値パーサ(`parseAnswerMethodValue`)は**空欄を `checkbox` に既定化**する。本チケットでは列定義の ○ に合わせ「空欄=行エラー(必須)」を推奨実装とするが、CSV パーサ挙動に合わせ「空欄=checkbox 既定」とするかは要確認(エクスポート出力は常に明示値のためラウンドトリップには影響しない)。
- **課題フラグ・スコープ**: DESIGN「要件① 2」の注記「対象は既存問題管理画面のスコープ全体(課題フラグは列に含めず既存値維持・新規 false)→要確認」は未確定のまま。X01 の列定義には影響しないが、X03/X04 での is_assignment 既定値として持ち越し確認が必要。
