# X04: インポートUI

## 目的

問題管理画面(`QuestionsManagement.tsx`)に xlsx インポートダイアログを追加する。DESIGN.md「要件①」§3 に基づき、フロー「ファイル選択(.xlsx)→ X01 のパース+バリデーション → エラー一覧表示 or 件数プレビュー → X03 の `import_questions` RPC 実行 → 結果トースト + `loadData()`」を実装する。エラー表示・プレビューの UI パターンは**既存 CSV インポート(課題管理)を踏襲**するが、**課題管理側のコードには一切触れない**。

## 対象ファイル

- `src/app/components/admin/QuestionsManagement.tsx`(変更)— インポート用 state・ハンドラ・ダイアログ UI を追加
- `src/app/lib/questionXlsx.ts`(**X01 で新設。参照のみ**)— パース+バリデーション
- `supabase/migrations/20260722000000_import_questions.sql`(**X03 で新設**)— `import_questions` RPC を `supabase.rpc()` で呼ぶ
- 参考(**変更禁止**): `src/app/components/admin/AssignmentsManagement.tsx`(既存 CSV インポートUI 1155-1249 行・エラー表示パターン 1206-1228・`handleImportFile`/`handleImportSubmit` 651-978)

## 実装手順

### 前提: X01 が提供する想定インターフェース(依存)

```ts
// src/app/lib/questionXlsx.ts (X01)

export interface ParsedQuestionRow {
  rowNumber: number;         // 元シート行番号(ヘッダー=1、最初のデータ行=2)
  id?: string;               // 空/未指定なら新規
  unitName: string;
  categoryName: string;
  text: string;
  optionA: string; optionB: string; optionC: string; optionD: string;
  correctAnswer: string;     // 昇順正規化済み(radio='A' / checkbox='A,C')
  answerMethod: AnswerMethod;// 'radio' | 'checkbox'
  explanation: string;
  isActive: boolean;
}

export interface QuestionImportError {
  rowNumber: number;         // 0 = ヘッダー/ファイル全体エラー
  column: string;            // 列名(例 '正解')。全体エラー時は '' 等
  reason: string;            // 理由(例 '正解はA/B/C/Dのいずれか1つ')
  message: string;           // 表示用整形済み文字列 '行N: [列名] 理由'
}

export interface QuestionParseResult {
  rows: ParsedQuestionRow[];
  errors: QuestionImportError[];
}

// SheetJS を動的 import して .xlsx を読み取り、ヘッダー検証+全行バリデーションを実施。
export async function parseQuestionsXlsx(data: ArrayBuffer): Promise<QuestionParseResult>;
```

X01 が別シグネチャ(例 `message` を持たず呼び出し側で整形)で確定した場合は、下記の表示ロジックを合わせて調整する(備考参照)。

### 手順

1. **import 追加**: `parseQuestionsXlsx`(および型 `ParsedQuestionRow`/`QuestionImportError`)を `../../lib/questionXlsx` から import。`useRef` を React import に追加。`lucide-react` から `Upload` アイコンを追加 import。

2. **state 追加**(QuestionsManagement コンポーネント内。既存の課題管理 state 名と揃えるが本ファイル内の新規追加):

   ```ts
   const [isImportDialogOpen, setIsImportDialogOpen] = useState(false);
   const importFileRef = useRef<HTMLInputElement | null>(null);
   const [importErrors, setImportErrors] = useState<QuestionImportError[]>([]);
   const [importRows, setImportRows] = useState<ParsedQuestionRow[]>([]);
   const [importing, setImporting] = useState(false);
   ```

   ```ts
   const resetImportState = () => {
     setImportErrors([]);
     setImportRows([]);
     setImporting(false);
     if (importFileRef.current) importFileRef.current.value = '';
   };
   ```

3. **ファイル選択→パース+バリデーション**(`handleImportFile`):

   ```ts
   const handleImportFile = async (file: File | null) => {
     resetImportState();
     if (!file) return;
     try {
       const buf = await file.arrayBuffer();
       const { rows, errors } = await parseQuestionsXlsx(buf);
       // ID有り + DB不存在 の事前チェック(admin は全問題を保持しているため照合可能)
       const knownIds = new Set(questions.map((q) => q.id));
       const idErrors: QuestionImportError[] = rows
         .filter((r) => r.id && !knownIds.has(r.id))
         .map((r) => ({
           rowNumber: r.rowNumber,
           column: 'ID',
           reason: `指定IDの問題が存在しません (${r.id})`,
           message: `行${r.rowNumber}: [ID] 指定IDの問題が存在しません (${r.id})`,
         }));
       const allErrors = [...errors, ...idErrors];
       if (allErrors.length > 0) {
         setImportErrors(allErrors);
         setImportRows([]);
         return;
       }
       if (rows.length === 0) {
         setImportErrors([{ rowNumber: 0, column: '', reason: '取り込み可能なデータ行がありません', message: '取り込み可能なデータ行がありません' }]);
         return;
       }
       setImportErrors([]);
       setImportRows(rows);
     } catch (e) {
       setImportErrors([{ rowNumber: 0, column: '', reason: 'ファイルの読み込みに失敗しました', message: 'ファイルの読み込みに失敗しました（.xlsx を選択してください）' }]);
     }
   };
   ```

   - **1件でもエラーがあれば取込不可**(`importRows` を空にして取込ボタンを無効化)。既存 CSV の全件中断挙動を踏襲。

4. **プレビュー算出**(エラーゼロ時。`useMemo` 推奨):

   ```ts
   const importPreview = useMemo(() => {
     const knownIds = new Set(questions.map((q) => q.id));
     const newCount = importRows.filter((r) => !r.id).length;
     const updateCount = importRows.filter((r) => r.id && knownIds.has(r.id)).length;

     const existingUnitNames = new Set(units.map((u) => u.name.trim()));
     const existingCatKeys = new Set(
       categories.map((c) => {
         const unitName = units.find((u) => u.id === c.unitId)?.name?.trim() ?? '';
         return `${unitName}::${c.name.trim()}`;
       })
     );
     const newUnits = new Set<string>();
     const newCategories = new Set<string>();
     for (const r of importRows) {
       const un = r.unitName.trim();
       if (un && !existingUnitNames.has(un)) newUnits.add(un);
       const key = `${un}::${r.categoryName.trim()}`;
       if (r.categoryName.trim() && !existingCatKeys.has(key)) newCategories.add(`${un} / ${r.categoryName.trim()}`);
     }
     return {
       newCount,
       updateCount,
       newUnits: Array.from(newUnits),
       newCategories: Array.from(newCategories),
     };
   }, [importRows, questions, units, categories]);
   ```

   - 「新規n件 / 上書きn件 / 自動作成される単元一覧 / 自動作成されるカテゴリ一覧」を表示するための集計(クライアント側の推定。実際の作成は RPC が行う)。

5. **取込実行→RPC 呼び出し**(`handleImportSubmit`):

   ```ts
   const handleImportSubmit = async () => {
     if (importRows.length === 0 || importErrors.length > 0) return;
     setImporting(true);
     try {
       const p_rows = importRows.map((r) => ({
         row_number: r.rowNumber,
         id: r.id ?? null,
         unit_name: r.unitName,
         category_name: r.categoryName,
         text: r.text,
         option_a: r.optionA,
         option_b: r.optionB,
         option_c: r.optionC,
         option_d: r.optionD,
         correct_answer: r.correctAnswer,
         answer_method: r.answerMethod,
         explanation: r.explanation,
         is_active: r.isActive,
       }));

       const { data, error } = await supabase.rpc('import_questions', { p_rows });
       if (error) {
         toast.error(`インポートに失敗しました: ${error.message}`);
         return;
       }
       const s = data as { inserted: number; updated: number; created_units: number; created_categories: number };
       toast.success(
         `インポート完了: 新規${s.inserted}件 / 上書き${s.updated}件` +
           (s.created_units ? ` / 単元${s.created_units}件作成` : '') +
           (s.created_categories ? ` / カテゴリ${s.created_categories}件作成` : '')
       );
       setIsImportDialogOpen(false);
       resetImportState();
       await loadData();
     } finally {
       setImporting(false);
     }
   };
   ```

   - RPC がエラー(全件ロールバック)を返した場合は `error.message`(例「行N: 指定IDの問題が見つかりません」)をトーストで通知し、ダイアログは閉じない(再操作可能に)。
   - **パラメータ名 `p_rows` は X03 の関数パラメータ名と一致必須**(不一致だと PostgREST が引数解決に失敗)。

6. **ダイアログ UI 追加**: CardHeader 内の `flex items-center gap-2` の `div`(357-574 行、X02 のエクスポートボタンと同じ並び)に「xlsxインポート」ボタン + `Dialog` を追加する。構成は課題管理の CSV インポートダイアログ(AssignmentsManagement 1155-1249)を踏襲:

   - **トリガ**: `variant="outline"` の `Button`（`<Upload className="h-4 w-4 mr-2" />` + ラベル「xlsxインポート」）。`Dialog` の `onOpenChange` で閉じたら `resetImportState()`。
   - **ファイル入力**: `<Input ref={importFileRef} type="file" accept=".xlsx" onChange=... />`。`onChange` で `void handleImportFile(e.target.files?.[0] ?? null)`。
   - **エラー表示**(既存パターン踏襲、最大20件+ほかN件):

     ```tsx
     {importErrors.length > 0 && (
       <div className="border rounded-md p-3 bg-red-50">
         <div className="font-semibold text-red-700 mb-2">エラー</div>
         <ul className="text-sm text-red-700 list-disc pl-5 space-y-1">
           {importErrors.slice(0, 20).map((e, idx) => (
             <li key={idx}>{e.message}</li>
           ))}
         </ul>
         {importErrors.length > 20 && (
           <div className="text-xs text-red-700 mt-2">ほか {importErrors.length - 20} 件</div>
         )}
       </div>
     )}
     ```

   - **プレビュー表示**(エラーゼロ かつ `importRows.length > 0`): 「新規 {newCount} 件 / 上書き {updateCount} 件」。`newUnits.length > 0` なら「自動作成される単元: …(カンマ区切り or リスト)」、`newCategories.length > 0` なら「自動作成されるカテゴリ: …」を表示。件数が多い場合は先頭のみ+「ほかN件」で省略。
   - **取込ボタン**: `disabled={importRows.length === 0 || importErrors.length > 0 || importing}`、ラベルは `importing ? 'インポート中...' : 'インポート'`、`onClick={() => void handleImportSubmit()}`。
   - **キャンセルボタン**: `setIsImportDialogOpen(false); resetImportState();`。

7. **課題管理を触らないことの担保**: 本チケットの変更は `QuestionsManagement.tsx` と(参照のみ)`questionXlsx.ts` / migration のみ。`AssignmentsManagement.tsx`・`lib/csv.ts` には一切変更を加えない。

## 完了条件

- 問題管理画面のツールバーに「xlsxインポート」ボタンが表示され、押下でダイアログが開く。
- `.xlsx` を選択すると X01 の `parseQuestionsXlsx` でパース+バリデーションが走る。
- バリデーションエラーが1件でもあれば「行N / 列名 / 理由」の一覧(最大20件+ほかN件)を表示し、取込ボタンが無効化される。
- ID有り+DB不存在の行がエラーとして事前検出される(クライアント照合)。
- エラーゼロ時、「新規n件 / 上書きn件 / 自動作成される単元・カテゴリ一覧」のプレビューが表示される。
- 取込実行で `supabase.rpc('import_questions', { p_rows })` が呼ばれ、成功時は `{inserted, updated, created_units, created_categories}` を用いた結果トースト表示 → ダイアログ閉 → `loadData()` で一覧更新。
- RPC エラー(全件ロールバック)時はエラートーストを表示し、DB は変更されない(部分反映なし)。
- 課題管理の既存 CSV インポート(`AssignmentsManagement.tsx` / `lib/csv.ts`)に一切変更がないこと。
- ラウンドトリップ: X02 でエクスポートした xlsx を無編集でインポートすると、全行が「上書き(実質 no-op)」として成功する。
- `npm run typecheck` / `npm run build` がエラーなく通る。

## 備考

- **要確認(バリデーション責務分担)**: 本チケットは「形式バリデーションは X01 の `parseQuestionsXlsx` に集約、ID存在チェックのみ X04 がクライアント照合(admin は全問題を保持)、最終的な整合は X03 RPC が全件ロールバックで担保」とした。X01 が ID 照合まで担う設計なら手順3の `idErrors` ブロックは不要。**X01 の責務範囲(DBアクセスを持つか)をすり合わせる**。
- **要確認(エラーオブジェクトの形)**: `QuestionImportError` に表示用 `message` を持たせる前提で表示ロジックを書いた。X01 が `{rowNumber, column, reason}` のみ返す場合、表示側で `行${rowNumber}: [${column}] ${reason}` に整形する(DESIGN §3-4 の「N行目/列名/理由」フォーマットに合わせる)。
- **要確認(row_number の送出)**: RPC のエラーメッセージを元シート行に一致させるため、`p_rows` に `row_number` を含める(X03 備考と対)。X03 が ordinality 運用に確定した場合は本フィールドを送らなくても動作するが、行番号がずれ得るため送出を推奨。
- **プレビューの単元/カテゴリ照合**: 単元は名前一致、カテゴリは「単元名::カテゴリ名」キーで既存判定する(X03 RPC の解決ロジックと同一の粒度)。同名単元が複数存在する DB では推定表示が実挙動と厳密一致しない可能性があるが、実際の作成有無は RPC 戻り値 `created_units`/`created_categories` の結果トーストが正となる。
- **UI 依存**: 既存 import 済みの `Dialog`/`Input`/`Label`/`Button` のみで構成し、R01 の未使用 ui 削除と衝突しない部品を使う。
