# R02: tsconfig 導入 + typecheck 整備

## 目的

現状このリポジトリには `tsconfig.json` が存在せず、ビルドは Vite(esbuild)によるトランスパイルのみで**型チェックがビルド工程に一切含まれない**(DESIGN.md S9)。この欠落が「存在しない supabase-js API 呼び出し(S8, `getSessionFromUrl`)」のような実バグを検出できなかった根本原因である。

本チケットで Vite + React + TypeScript の標準 `tsconfig.json` を追加し、`npm run typecheck`(`tsc --noEmit`)を導入する。これにより以降の全チケット(X01 の純関数実装、R03〜R12 の改修)に対する**型レベルの安全網**を用意する。挙動は変えない(型注釈・設定・型エラー修正のみ)。

## 対象ファイル

### 新規

- `tsconfig.json`(リポジトリルート)… アプリ(`src`)向け型チェック設定。**現状不在を確認済み**(`find` で `tsconfig*.json` ヒット 0)
- `src/vite-env.d.ts` … `/// <reference types="vite/client" />` を置き `import.meta.env` の型を解決

### 変更

- `package.json`
  - `scripts` に `"typecheck": "tsc --noEmit -p tsconfig.json"` を追加
  - `devDependencies` に `typescript`(未インストールを確認済み)と `@types/react-dom`(未インストール、`@types/react` は導入済み)を追加
- `src/app/components/quiz/Quiz.tsx` … Header へ渡している未定義 prop `isQuizAttempt` を削除(型エラー TS2322 の解消。挙動不変=下記備考)

### 変更(要確認・R11 との境界)

- `src/app/components/auth/ResetPassword.tsx`(28行目付近)
- `src/app/components/auth/AcceptInvite.tsx`(88行目付近)
  - `supabase.auth.getSessionFromUrl(...)` が supabase-js 2.56.0 に存在せず TS2339。これは S8 = **R11 の担当**。R02 では typecheck をグリーンにするための**最小抑制**(`@ts-expect-error` + `// TODO(R11/S8)` コメント)のみ行い、正しい API への置換(`setSession`/`exchangeCodeForSession` の選定)は R11 に委ねる。この境界は要確認(最終報告に記載)

## 実装手順

1. **ブランチ作成**: `feature/R02`(R01 マージ後に切る)。
2. **devDependencies 追加**: `npm i -D typescript@~5.6.3 @types/react-dom@~18.3.1`(react/react-dom は 18.3.1 系。`@types/react` は既存)。
3. **`tsconfig.json` 追加**(推奨内容。strict は原則有効・ただし下記 strict 度の調整あり):
   ```json
   {
     "compilerOptions": {
       "target": "ES2020",
       "useDefineForClassFields": true,
       "lib": ["ES2020", "DOM", "DOM.Iterable"],
       "module": "ESNext",
       "skipLibCheck": true,
       "moduleResolution": "bundler",
       "allowImportingTsExtensions": true,
       "resolveJsonModule": true,
       "isolatedModules": true,
       "moduleDetection": "force",
       "noEmit": true,
       "jsx": "react-jsx",
       "strict": true,
       "noUnusedLocals": false,
       "noUnusedParameters": false,
       "noFallthroughCasesInSwitch": true,
       "baseUrl": ".",
       "paths": { "@/*": ["./src/*"] }
     },
     "include": ["src"]
   }
   ```
   - **strict 度の推奨**: `strict: true` を採用(`noImplicitAny`/`strictNullChecks` 等を有効化=S8 系バグの再発防止に必須)。ただし `noUnusedLocals` / `noUnusedParameters` は**初回導入では無効**にする(理由=備考「型エラー実測」)。
   - **`include` は `src` のみ**。`supabase/functions/server/`(Deno ランタイム・`jsr:` / `npm:` / `Deno.*` を使用)と `tests/e2e`(Playwright)は**含めない**。含めると大量の解決不能エラーになる。
   - `paths` の `@/*` は `vite.config.ts` の alias と一致させる。
4. **`src/vite-env.d.ts` 追加**: `/// <reference types="vite/client" />` の 1 行。これで `adminApi.ts` / `supabase.ts` の `import.meta.env`(TS2339 ×4)が解消。
5. **`@types/react-dom` により `main.tsx` の `react-dom/client`(TS7016)が解消**することを確認。
6. **Quiz.tsx の prop 修正**: `<Header ... isQuizAttempt={true} ... />` の `isQuizAttempt={true}` 行を削除。`HeaderProps` は `courseType?` と `onHomeClick?` のみ定義し `isQuizAttempt` を受け取らない・参照もしないため、削除しても描画・挙動は不変(TS2322 解消)。
7. **S8 の 2 箇所を最小抑制**: `ResetPassword.tsx` / `AcceptInvite.tsx` の `getSessionFromUrl` 呼び出し行の直前に
   ```ts
   // @ts-expect-error TODO(R11/S8): getSessionFromUrl は supabase-js 2.56 に存在しない。R11 で正規APIに置換
   ```
   を挿入。R11 が正規 API へ置換した時点で当該エラーが消え、`@ts-expect-error` が「未使用ディレクティブ(TS2578)」となって除去を強制する自己クリーニング設計。**ランタイム挙動は現状のまま**(バグは温存=R11 が実修正)。
8. **`npm run typecheck` を実行し exit 0** を確認(残存 `error TS` が 0 件)。
9. **`npm run build` を再実行し exit 0**(型設定追加でビルドが壊れていないこと)。
10. **単独 PR 作成**。

## 完了条件

1. `test -f tsconfig.json` が exit 0(ルートに tsconfig.json 実在)。
2. typecheck スクリプトが登録されている:

   ```
   npm run typecheck                                  # exit 0
   npx tsc --noEmit -p tsconfig.json 2>&1 | grep -c "error TS"   # => 0
   ```

5. `npm run build` が **exit 0**(回帰なし)。
6. `isQuizAttempt` が Quiz.tsx から消えている:
   ```
   grep -rn "isQuizAttempt" src/ | wc -l              # => 0
   ```

## 備考

### 型エラー実測(本チケット着手前に一時 tsconfig で計測、計測用ファイルは未コミット・削除済み)

- **フル strict + `noUnusedLocals`/`noUnusedParameters` 有効**: `error TS` **15 件**。
- **strict 無効 + `vite/client` 型あり(構造的エラーのみ)**: **3 件**。

内訳と本チケットでの扱い:

| 種別 | 件数 | 代表例 | R02 での対応 |
|------|------|--------|--------------|
| `import.meta.env` の型不足(TS2339) | 4 | `adminApi.ts(5,40)`, `supabase.ts(3,33)` | `src/vite-env.d.ts` で解消 |
| `react-dom/client` 型不足(TS7016) | 1 | `main.tsx(2,30)` | `@types/react-dom` 追加で解消 |
| 未使用ローカル/import(TS6133/6192) | 7 | `AdminDashboard(15,9) 'user'`, `Result.tsx(6,1) All imports unused`, `Home(11,9) 'user'`, `AssignmentsManagement(34/69)`, `CategoriesManagement(28)` | **`noUnused*` を無効化して回避**(下記線引き) |
| `getSessionFromUrl` 不在(TS2339) | 2 | `ResetPassword(28,31)`, `AcceptInvite(88,41)` | **S8=R11 担当**。R02 は `@ts-expect-error` で抑制 |
| Header 未定義 prop(TS2322) | 1 | `Quiz.tsx(197,9) isQuizAttempt` | Quiz.tsx から prop 削除(挙動不変) |

### 修正範囲の線引き(推奨)

- **R02 が直す**: 設定起因 5 件(vite-env.d.ts + @types/react-dom)+ Quiz Header 1 件。これらは他チケットが所有しない・低リスク・挙動不変。
- **R02 が抑制のみ(実修正しない)**: S8 の 2 件。R11 が `getSessionFromUrl` を正規 API に置換する専任チケットのため、R02 が意味的修正まで踏み込むと R11 とスコープが重複し、かつ置換先 API の選定(`setSession` か `exchangeCodeForSession` か)を R11 の設計判断から奪う。`@ts-expect-error` により typecheck をグリーンにしつつ R11 の担当を保全する。
- **`noUnusedLocals`/`noUnusedParameters` を初回は無効**: 未使用 7 件は瑣末だが、対象ファイル(Result.tsx=R10/S7、Home/AdminDashboard=perf 系、AssignmentsManagement=R06)が後続チケットで編集される。ここで有効化して一括削除するとマージ衝突を招くため、R02 は「安全網の土台」に徹し未使用整理は各担当チケットまたは後日のスイープに委ねる。将来 `true` へ引き上げ可能な設計にしておく。

### 要確認事項(PM/オーナー)

- **R02 完了条件「typecheck exit 0」と R11(S8)所有権の緊張**: TICKETS.md では R11 は R02 に依存(R02 が先行)。したがって R02 完了時点で `getSessionFromUrl` の実バグは未修正のまま残る。上記のとおり R02 は `@ts-expect-error` 抑制で typecheck をグリーンにする方針を推奨するが、代替として「S8 の 2 行修正を R02 に前倒し(R11 は E2E 検証専任に縮小)」も選択肢。どちらを採るかは要確認。
- 抑制方式を採らず該当 2 ファイルを tsconfig の `exclude` に入れる案は、ファイル全体の型被覆を失うため非推奨(ピンポイントの `@ts-expect-error` が上位)。
