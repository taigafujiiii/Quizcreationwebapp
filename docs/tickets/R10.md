# R10: 楽観ロック欠落補完（S5）+ エラー通知（S10）+ Resultクラッシュ防御（S7前半）

## 目的

堅牢性の3点を補完する。いずれも正規UIの見た目は不変。

- (a) **S5**: `companies` 更新だけ楽観ロック（`updated_at` 一致条件）が欠落。他画面（`/admin/users` = `server/index.ts:730-744`）は一貫実装済み。複数管理者の同時編集で後勝ちの取りこぼしが起きる。
- (b) **S10**: `CompaniesManagement.tsx` / `UsersManagement.tsx` のデータ取得で一部エラーを無通知で握りつぶし。他画面は `toast.error` で一貫。
- (c) **S7前半**: `Result.tsx` が `location.state` を未チェックで分割代入するため、リロード/直アクセス/`state`なし遷移で白画面クラッシュ。

## 実装手順

### (a) companies 更新の楽観ロック（S5）

`/admin/users` の実装（`server/index.ts:689, 730-744`）を踏襲する。

1. `adminApi.ts` `updateCompany` に `updatedAt` を追加:
   ```ts
   updateCompany: async (companyId: string, payload: { allowedUnitIds?: string[]; pin?: string | null; updatedAt?: string }) => {
     return adminFetch<{ success: true; updatedAt?: string | null }>(`/admin/companies/${companyId}`, {
       method: 'PATCH', body: JSON.stringify(payload),
     });
   },
   ```
2. `server/index.ts` `PATCH /admin/companies/:id`（355-392行）:
   - body から `const prevUpdatedAt = typeof body?.updatedAt === 'string' ? body.updatedAt : null;`
   - update チェーンに `if (prevUpdatedAt) q = q.eq('updated_at', prevUpdatedAt);` を付与。
   - `.select('updatedAt:updated_at').maybeSingle()` を付け、`if (prevUpdatedAt && !data) return c.json({ error: 'Conflict: already updated by another user' }, 409);`
   - 成功時 `return c.json({ success: true, updatedAt: (data as any)?.updatedAt ?? null });`
   - ※現状の PATCH は `.update(updates).eq('id', companyId)`（select無し）なので、select 付与とレスポンス形の変更が必要。`companies_set_updated_at` トリガ（`20260211000000_companies.sql:14-17`）で `updated_at` は自動更新される。
3. `CompaniesManagement.tsx` `handleSaveUnits`（120-138行）:
   - `adminApi.updateCompany(companyToEdit.id, { allowedUnitIds: editAllowedUnits, pin: pinValue, updatedAt: companyToEdit.updatedAt })`
   - 返り値の `updatedAt` を用いてローカル state を更新（`setCompanies(prev => prev.map(c => c.id===... ? {...c, allowedUnitIds, pin, updatedAt: res.updatedAt ?? c.updatedAt} : c))`）。
   - 409（競合）時は `UsersManagement.handleSaveEdit`（297-300行）に倣い `toast.error('保存に失敗しました（他のユーザーが先に更新した可能性があります）')` + `await loadData()` で再取得。エラー文字列に `409` / `Conflict` を含む場合を競合として分岐。
   - `GET /admin/companies`（324行）は既に `updatedAt` を返すため、`companyToEdit.updatedAt` は取得済み。`Company.updatedAt` 型も定義済み（`types.ts:23`）。

### (b) エラー無通知に toast.error 追加（S10）

- `CompaniesManagement.tsx` `loadData`（36-50行）: 外側 catch には既に `toast.error('データの取得に失敗しました')` があるが、**units 取得失敗が握りつぶし**（44行 `if (!unitRes.error) setUnits(...)` の else が無い）。`else toast.error('単元の取得に失敗しました')` を追加。
- `UsersManagement.tsx` `loadUsers`（68-93行）: `Promise.allSettled` の結果で
  - units（84-86行）: `else`（rejected もしくは `unitsResult.value.error`）で `toast.error('単元の取得に失敗しました')`。
  - companies（88-90行）: `else`（rejected）で `toast.error('会社一覧の取得に失敗しました')`。
  - users 失敗は既存の `setLoadError` 維持（全画面エラー表示のため）。units/companies は部分失敗のため toast で通知（他画面の一貫パターン）。

### (c) Result の location.state null防御（S7前半）

`Result.tsx:14-17` の分割代入前にガードを入れる。`Quiz.tsx:20`（`location.state || {}`）＋各種ガードの防御パターンを踏襲。Result は `StudentRoute` 配下なので未選択会社時は `/select-company` に既にリダイレクトされるが、`state` 欠落は別問題として `/` へ戻す。

```tsx
export const Result: React.FC = () => {
  const location = useLocation();
  const navigate = useNavigate();
  const state = location.state as { questions?: Question[]; answers?: QuizAnswer[] } | null;

  useEffect(() => {
    if (!state?.questions || !state?.answers || state.questions.length === 0) {
      navigate('/', { replace: true });
    }
  }, [state, navigate]);

  if (!state?.questions || !state?.answers || state.questions.length === 0) {
    return null; // リダイレクト中は何も描画しない（白画面クラッシュを回避）
  }

  const { questions, answers } = state;
  // 以降は既存ロジック（results計算〜JSX）を維持
```

- `percentage` の `totalCount===0` 除算（62行 `Math.round((correctCount/totalCount)*100)`）も、上記ガードで `questions.length===0` を弾くため NaN を回避できる。念のため `totalCount ? Math.round(...) : 0` にしてもよい。
