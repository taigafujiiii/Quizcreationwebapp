# X02: エクスポート機能

## 目的

問題管理画面(`QuestionsManagement.tsx`)に、4択問題を xlsx でエクスポートする機能を追加する。DESIGN.md「要件①」に基づき、**エクスポートの出力列定義を単一の真実**とし、後続の X04(インポートUI)がラウンドトリップ(無編集で再インポート→全行 no-op 上書き)を保証できる形式で出力する。エクスポート範囲は **全件** と **現在の絞り込み結果** の2モードを提供する。

## 対象ファイル

- `src/app/components/admin/QuestionsManagement.tsx`(変更)— エクスポートボタン追加・呼び出しロジック追加
- `src/app/lib/questionXlsx.ts`(**X01 で新設。本チケットでは参照のみ・変更しない**)
- 参考(変更しない): `src/app/components/admin/AssignmentsManagement.tsx`(既存 CSV テンプレDLの Blob ダウンロード実装パターン `downloadImportTemplate` 635-649 行)
- 参考(変更しない): `src/app/types.ts`(`Question` / `Category` / `Unit` 型)

## 実装手順

### 前提: X01 が提供する想定インターフェース(依存)

X01 実装前でも本チケットを書けるよう、`questionXlsx.ts` の公開APIを以下の想定で参照する。**X01 が確定した実シグネチャと異なる場合は呼び出し側(本チケットのコード)を合わせて調整する**(備考参照)。

```ts
// src/app/lib/questionXlsx.ts (X01)

// 列定義(単一の真実)。順序どおりのヘッダー配列。
// ['ID','単元','カテゴリ','問題文','選択肢A','選択肢B','選択肢C','選択肢D','正解','回答方式','解説','公開']
export const QUESTION_XLSX_HEADERS: readonly string[];

// エクスポート1件分の入力(単元名・カテゴリ名は呼び出し側で解決済みを渡す)
export interface QuestionExportInput {
  question: Question;   // types.ts の Question(id/optionA..D/correctAnswer/answerMethod/explanation/isActive を含む)
  unitName: string;     // categoryId から解決した単元名
  categoryName: string; // categoryId から解決したカテゴリ名
}

// Question[] → xlsx(ArrayBuffer)。SheetJS を動的 import(await import('xlsx'))で遅延読込。
// 内部で正解の昇順正規化・公開列の '公開'/'非公開' 変換・ID(UUID)出力を行う。
export async function questionsToXlsx(items: QuestionExportInput[]): Promise<ArrayBuffer>;
```

（X01 が「行変換の純関数(`toXlsxRows(items): string[][]`)」と「SheetJS 書き出し」を分離して公開する場合も、本チケットは高レベルの `questionsToXlsx` を呼ぶだけで良い。分離公開なら X02 側で `new Blob([XLSX.write(...)])` 相当を書く必要はない。）

### 手順

1. **import 追加**: `QuestionsManagement.tsx` 冒頭に `import { questionsToXlsx, QuestionExportInput } from '../../lib/questionXlsx';` を追加。`lucide-react` から `Download` アイコンを追加 import(既存 import 行に追記)。

2. **単元名・カテゴリ名の解決ヘルパー**: `Question` は `categoryId` のみ保持し `unitId`/名称を持たない。エクスポート対象配列から `QuestionExportInput[]` を組み立てる関数を追加する。既存の `getCategoryName`(269-271)・`getUnitNameByCategoryId`(273-277)と同じ解決経路(`categoryId → categories.find → category.name` / `categoryId → categories.find → category.unitId → units.find → unit.name`)を使う。件数が多いケースを想定し、O(1) 参照用に `categoryById` / `unitById` の `Map` をローカルに構築してから解決する(R05 の Map 化最適化と整合)。解決不能時は `getCategoryName` 同様 `'不明'` にフォールバック(データ不整合でもエクスポートが落ちないこと)。

   ```ts
   const buildExportInputs = (items: Question[]): QuestionExportInput[] => {
     const categoryById = new Map(categories.map((c) => [c.id, c]));
     const unitById = new Map(units.map((u) => [u.id, u]));
     return items.map((q) => {
       const cat = categoryById.get(q.categoryId);
       const unit = cat ? unitById.get(cat.unitId) : undefined;
       return {
         question: q,
         categoryName: cat?.name ?? '不明',
         unitName: unit?.name ?? '不明',
       };
     });
   };
   ```

3. **ファイル名生成**: DESIGN 指定の `questions_YYYYMMDD_HHmm.xlsx`。ローカル時刻でゼロ埋め。

   ```ts
   const buildExportFileName = () => {
     const d = new Date();
     const p = (n: number) => String(n).padStart(2, '0');
     const stamp = `${d.getFullYear()}${p(d.getMonth() + 1)}${p(d.getDate())}_${p(d.getHours())}${p(d.getMinutes())}`;
     return `questions_${stamp}.xlsx`;
   };
   ```

4. **エクスポート実行関数**: 引数で対象配列(全件=`questions` / 絞り込み結果=`filteredQuestions`)を受け取り、X01 の `questionsToXlsx` で ArrayBuffer を取得 → **Blob + URL.createObjectURL** でダウンロード。既存 `downloadImportTemplate`(AssignmentsManagement 635-649)と同じ `<a>` 生成・click・remove・revokeObjectURL パターンを踏襲する。

   ```ts
   const handleExport = async (scope: 'all' | 'filtered') => {
     const target = scope === 'all' ? questions : filteredQuestions;
     if (target.length === 0) {
       toast.error('エクスポート対象の問題がありません');
       return;
     }
     try {
       const buf = await questionsToXlsx(buildExportInputs(target));
       const blob = new Blob([buf], {
         type: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet',
       });
       const url = URL.createObjectURL(blob);
       const a = document.createElement('a');
       a.href = url;
       a.download = buildExportFileName();
       document.body.appendChild(a);
       a.click();
       a.remove();
       URL.revokeObjectURL(url);
       toast.success(`${target.length}件をエクスポートしました`);
     } catch (e) {
       toast.error('エクスポートに失敗しました');
     }
   };
   ```

5. **ボタン配置**: CardHeader 内、`選択削除`ボタンと`新規作成`Dialog を含む `flex items-center gap-2` の `div`(357-574 行)に、`Download` アイコン付きの2ボタンを追加する。新規 UI 依存(dropdown-menu 等、R01 で削除対象になり得る)を増やさないため、素の `Button`(既存 import 済)を2つ置く方式とする。

   - `全件エクスポート`: `onClick={() => void handleExport('all')}`、`disabled={loading || questions.length === 0}`
   - `絞り込み結果をエクスポート`: `onClick={() => void handleExport('filtered')}`、`disabled={loading || filteredQuestions.length === 0}`
   - どちらも `variant="outline"`。ラベルにアイコン `<Download className="h-4 w-4 mr-2" />`。

6. **出力仕様の遵守(X01 側で担保・本チケットで確認)**:
   - **ID列**: `question.id`(UUID)をそのまま出力。空にしない(既存問題は必ず ID を持つ)。これにより再インポート時に「ID一致→上書き」となる。
   - **正解**: 昇順・重複除去で正規化して出力(例 checkbox の `C,A` → `A,C`)。DB 保存値が未ソートでもエクスポート出力は正規形にする(ラウンドトリップ安定性のため)。正規化ロジックの所在は X01(備考の要確認参照)。
   - **公開列**: `isActive === true` → `公開`、`false` → `非公開`(DESIGN 列定義 §2)。
   - **回答方式列**: `radio` / `checkbox` をそのまま出力(日本語表記は入力時のみ受理)。
   - **単元/カテゴリ列**: 手順2で解決した名称。

## 完了条件

- 問題管理画面のツールバーに「全件エクスポート」「絞り込み結果をエクスポート」の2ボタンが表示される。
- 全件エクスポートで `questions` 全件、絞り込みエクスポートで `filteredQuestions`(単元/カテゴリ絞り込み反映済み)が出力される。
- ダウンロードファイル名が `questions_YYYYMMDD_HHmm.xlsx` 形式。
- 出力 xlsx の1行目が `QUESTION_XLSX_HEADERS`(12列)と一致。ID列に UUID、正解列が昇順正規化済み、公開列が `公開`/`非公開`。
- ダウンロード実装が Blob + `URL.createObjectURL` + `<a>.click()` + `revokeObjectURL`(メモリリークなし)。
- SheetJS はメインバンドルに載らない(X01 の動的 import 経由。エクスポートボタン押下まで xlsx チャンクがロードされないこと)。
- 課題管理(AssignmentsManagement)の既存 CSV 機能に一切変更がないこと。
- `npm run typecheck` / `npm run build` がエラーなく通る。

## 備考

- **要確認(正解正規化のタイミング)**: 正解の昇順正規化を X01(`questionsToXlsx` 内)で行う想定で記述した。X01 が「変換は無加工・正規化は呼び出し側」の方針を採る場合、手順4の前に本チケットで `parseCorrectAnswerList`(QuestionsManagement 44-60 に既存、昇順ソート済)を使って正規化した値を `QuestionExportInput` に載せる必要がある。**どちらで正規化するかは X01 の設計確定に合わせる**(X01 とインターフェースを揃えること)。DESIGN §2 の「正解: 昇順正規化」を満たせばどちらでも可。
- **エクスポート範囲の UI**: DESIGN は「全件/絞り込み結果の2モード」とのみ規定。本チケットは新規 UI 依存を避けるため2ボタン方式を採用したが、`ui/dropdown-menu` を1メニューにまとめる案も可(その場合 R01 の未使用 ui 削除対象と衝突しないか要確認)。
- **課題フラグ**: エクスポート列に課題フラグ(`isAssignment`)は含めない(DESIGN §2 の12列に無い)。エクスポート→再インポート時、X03 は `is_assignment` に触れず既存値を維持するため、課題問題をエクスポート・再取込しても課題フラグは保持される。
- **大量件数**: SheetJS の `aoa_to_sheet` は同期処理。数千件規模で UI がわずかにブロックし得るが、現行データ規模では許容。将来的に問題があれば Web Worker 化を別チケットで検討。
